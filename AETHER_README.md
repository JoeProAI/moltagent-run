# AETHER — The Weightless AI Constellation

**Master Orchestration Layer. Global Swarm Routing. Zero Gravity.**

I am JoePro, and this is AETHER. This layer sits above the local execution hardware, acting as the master cloud orchestrator. It is not the brain, and it is not the local engine—it is the cosmic highway.

## Architecture Doctrine (The Canon)
AETHER adheres strictly to the `joepro-systems` unified orchestration canon:
*   **AETHER Above**: Master orchestration layer, global swarm routing, cloud workload coordination.
*   **NOESIS Local and Sovereign**: The local execution authority (MSI Raider 18 AI HX 5080) handling sovereign retrieval and final cinematic polish.
*   **OpenClaw Brain as Memory Truth**: AETHER is strictly read-first. It does not maintain a parallel long-term memory store. OpenClaw holds the truth.
*   **Firestore for Orchestration State**: Real-time transient state tracking for the constellation UI.
*   **Convex for NOESIS Product State**: The local database for NOESIS.

## What AETHER Actually Does
1.  **The Constellation Canvas**: A pristine WebGL representation of transient Firestore states. Agents are glowing celestial bodies. Zoom from intimate single-agent view to massive cloud swarms.
2.  **Global Swarm Routing**: Spins up massive parallel crews (e.g., X Growth Debate Engine) in the cloud via Gemini.
3.  **Handoff to NOESIS**: When raw compute is done, AETHER executes Bridge Contracts (`/bridge/local-polish`, `/bridge/session-summary-writeback`) to hand off data to NOESIS for local sovereign execution and OpenClaw memory storage.

## How to Run

1.  **Start the Frontend Visualizer**: `npm run dev`
2.  **Start the Backend Engine**: `node backend/engine.js` (Requires `service-account.json` to listen to Firestore orchestration state).
3.  **Ensure NOESIS is Running**: AETHER expects NOESIS to be alive on your local port to answer Bridge Contract calls.
